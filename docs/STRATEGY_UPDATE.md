## 1. Что изменилось в постановке

### 1.1 Тема диплома уточнена
**Новая формулировка:** «Прогнозирование временных рядов за счёт обучаемых параметров разложения на компоненты и нейросетевых механизмов учёта долгосрочных зависимостей».

**Ключевые акценты:**
- **Обучаемые параметры декомпозиции** (learnable decomposition) — не фиксированная статистическая декомпозиция (HW, STL), а декомпозиция как часть нейросетевой архитектуры с обучаемыми весами.
- **Механизмы учёта долгосрочных зависимостей** — attention, auto-correlation, frequency-domain attention, multi-scale mixing и т.д.

### 1.2 Helformer больше не центральная модель
Helformer (Kehinde et al., 2025) использовал утечку данных при обучении. После исправления утечки результаты резко ухудшились. Это значит:
- Helformer **нельзя** оставлять главным научным результатом
- Helformer можно упоминать как архитектурную идею (HW + Transformer) и как один из экспериментальных вариантов
- Нужна **новая центральная линия** на основе доверенных, воспроизводимых моделей

### 1.3 Репозиторий — автономный проект
Исторически репозиторий был общим с Лыковым. Теперь:
- Все артефакты Лыкова (`Praktika_4_Lykov.docx`, BTC-эксперименты) — **шум**, не часть моего диплома
- Нужно расчистить кодовую базу и стабилизировать мой автономный контур

### 1.4 M5 снят с обязательного статуса
M5 — иерархический датасет (hierarchical forecasting). Тема работы — point forecasting + decomposition. M5 требует другой методологии и непропорционально много усилий. **Решение: исключить M5 с обоснованием, компенсировать расширенным M4.**

## 3. Новая центральная линия диплома

### Исследовательский вопрос
**Насколько эффективны обучаемые механизмы декомпозиции временных рядов на компоненты (тренд, сезонность, остаток) по сравнению с фиксированными статистическими методами, и какова роль нейросетевых механизмов учёта долгосрочных зависимостей (attention, auto-correlation, frequency-domain) в качестве прогноза?**

### Архитектурная ось
```
Фиксированная декомпозиция          →    Обучаемая декомпозиция
(HW, STL, MODWT)                         (Autoformer, DLinear, TimeMixer, FEDformer)
    ↓                                         ↓
Классика на компонентах              →    Нейросеть на компонентах
(ARIMA, ETS)                              (attention, MLP, auto-correlation)
    ↓                                         ↓
Гибриды: статистика + нейросеть      →    End-to-end: декомпозиция + прогноз внутри сети
```

### Что сравниваем
1. **Классические модели** (ARIMA, ETS, Prophet) — baseline
2. **Простые нейросетевые** с learnable decomposition (DLinear, N-BEATS interpretable)
3. **Transformer-based** с learnable decomposition (Autoformer, FEDformer)
4. **Гибриды** (декомпозиция + нейросеть для компонент)
5. *(Опционально)* Helformer как пример «архитектурной идеи HW + attention»

### Что доказываем / проверяем
- H1: Обучаемая декомпозиция повышает качество прогноза по сравнению с фиксированной HW/STL
- H2: Более сложные механизмы (attention) не всегда лучше простых (linear) на том же базисе декомпозиции
- H3: Комбинирование декомпозиции с разными механизмами зависимостей даёт разные результаты на разных типах рядов

## 5. Главный технический вопрос: как интегрировать новые модели?

### Вариант A: Time-Series-Library (TSLib)
- **Плюсы:** Autoformer, FEDformer, DLinear, PatchTST, iTransformer, TimeMixer — все уже реализованы. Единый интерфейс. PyTorch.
- **Минусы:** Заточена под multivariate long-term forecasting с фиксированными датасетами (ETT, Weather, Electricity). Адаптация под M3/M4 (univariate, разные горизонты) потребует написания адаптера.
- **Рекомендация:** Использовать TSLib как источник реализаций, но написать свой eval-wrapper для M3/M4.

### Вариант B: Реализовать DLinear/Autoformer с нуля
- **Плюсы:** Полный контроль, чистая интеграция с существующим pipeline.
- **Минусы:** DLinear — тривиально (30 строк). Autoformer — нетривиально (~400 строк).
- **Рекомендация:** DLinear реализовать самостоятельно (очень просто). Autoformer / PatchTST — взять из TSLib.

### Вариант C: Комбинировать
- DLinear — своя реализация (тривиальная)
- Autoformer, FEDformer, PatchTST — из TSLib с eval-wrapper
- N-BEATS, TimesNet — уже реализованы в проекте
- ARIMA, ETS, Prophet — уже реализованы

**Рекомендация: Вариант C.** Это быстро, надёжно и даёт максимальное покрытие при минимальных усилиях.
